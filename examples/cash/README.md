# Демо «Касса» для HTML_DBMS/4

Исходник: `tests/fixtures/cash_input.xlsx` (SHA-256 `4c3a6e2ca3ccef53f9b8ce6989dc483bcd46a69aff3a418a0bae744aa43bcd0a`). Книга передана пользователем как обезличенная.

## Архитектура

- 1 физический HTML-файл, 1 опубликованная БД «Касса».
- 11 независимых криптографических JSON-цепочек: `transactions` и 10 справочников (все исходные листы). В `transactions.rows` только 1641 заполненная операция, пропуски строк Excel не материализуются.
- В транзакциях только ID для 5 связей: `toTypeId`, `toId`, `typeId`, `fromTypeId`, `fromId`. Таблица отображает имена из справочников; ввод — через связанные выпадающие списки.
- Case-insensitive сопоставление сохраняется. Тестовая книга содержит 32 синтетические категории и 1641 синтетический комментарий, оригинальные подписи и тексты заменены. Происхождение транзакций хранится в `excelRow`; номера строк Excel **не хранятся в справочниках**. Соответствие строкам справочников проверяется по исходному XLSX fixture. Контрольная SHA-256 книги сохранена.
- 6 аналитических отчётов — **только JS views**. Результаты не сохраняются в отдельные JSON-документы. Формулы Excel повторяются с учётом направления операции, периода, ДД, категории, субъекта и источника.
- Пять исходных отчётов имеют подтверждённый дефект: Excel суммирует 31 из 32 видимых категорий. Новая модель включает все категории. Excel cache — только диагностика, нормативная проверка — точный oracle по исходным операциям.

## Сборка

Находясь в корне репозитория:

```sh
python3 build.py
cash_tmp=$(mktemp -d)
node examples/cash/build-demo.cjs tests/fixtures/cash_excel_extracted.json "$cash_tmp/cash.html"
python3 tests/compare_excel.py tests/fixtures/cash_input.xlsx "$cash_tmp/cash.html"
```

Дополнительно браузерное представление (при наличии Playwright и Chromium):

```sh
python3 tests/browser_cash_ui.py
```

Тест `browser_cash_ui.py` проверяет настоящий UI и выпадающие списки в браузере, но использует mock RPC host. Криптография/восстановление цепочек проверяются независимо Node Web Crypto в builder и XLSX comparison. Для полного E2E с реальным WebCrypto в браузере имеется отдельный тест `browser_cash.py`: он требует разрешённой навигации к loopback HTTP; в контейнерной среде Chromium возвращает `ERR_BLOCKED_BY_ADMINISTRATOR`, и результат **не заявлен как PASS**.

## Ограничения

Не создаются Excel-пустые строки; нет механизма транзакционной атомарности поверх нескольких справочников при редактировании. Дополнительные Excel-листы с произвольными формулами не исполняются: только шесть воспроизведённых представлений. Демо не заменяет независимый криптографический аудит HTML DBMS.

## Дополнения: полный журнал, диаграммы и редактирование справочников

- Журнал показывает **все 1641 исходные транзакции в одной таблице без пагинации**. Доступны поиск и фильтр периода. В iframe одна вертикальная прокрутка для приложения, в широких таблицах сохраняется горизонтальная прокрутка.
- Для демо HTML применяется полноэкранная раскладка под узкой системной панелью HTML DBMS, без ограничения ширины 1450px и высоты iframe 72vh. Универсальное ядро СУБД не меняется.
- Поле `План/Факт` полностью исключено из JSON-транзакций и UI. В исходном Excel оно заполнено `План` у **трёх** операций (все относятся к третьему типу справочника); сами операции и этот тип остаются. Их участие в агрегатах сохраняется в точности по оригинальным `SUMIFS`.
- В каждом из шести вычисляемых view отображается гистограмма остатков по категориям, в стиле горизонтальной диаграммы на листе `Участники(Фонд)` исходной книги. Значения вычисляются из текущих JSON-цепочек; диаграммы не хранятся в DBMS.
- Во вкладке **Справочники** доступны `+ Справочник` (создание самостоятельной JSON-цепочки через `db.createDocument`), `+ Запись` и `Изменить` (RFC 6902 JSON Patch). ID записей неизменяемы при редактировании. Наименования проверяются на дубликаты без учёта регистра. В типе сущности хранится стабильная привязка `documentAlias`, поэтому переименование пользовательской подписи не разрывает связи.
- После изменений нужно нажимать системное **Сохранить HTML**. Исторические состояния продолжают восстанавливаться по старым head. Автоматическое объединение конкурентных правок не предоставляется.

### Дополнительные тесты

```sh
node tests/cash_crud.test.cjs
python3 tests/browser_cash_ui.py
```

Первый тест использует настоящий Node Web Crypto и проверяет создание/редактирование справочников и `verifyDatabase`. Второй выполняется в Chromium с mock RPC только для UI. Полный `file://` E2E без shim отдельно не подтверждён.

## Приёмка пользовательских записей (исправление iframe sandbox)

Системная оболочка запускает entry внутри `iframe sandbox="allow-scripts"` **без `allow-forms`**. В этом режиме Chromium запрещает native HTML form submit; обработчики `submit` не вызываются даже с `preventDefault()` (наблюдение на реально встроенном iframe). Исправление не ослабляет sandbox: действия сохранения выполняются через явные `button[type=button]` и `click` с пользовательской валидацией, запросом разрешения **в оболочке**, криптографическим append и обновлением интерфейса. Ошибки/отмена показываются внутри формы (`role="alert"`). Общая кнопка «Сохранить» скачивает новый HTML с последним root head.

Справочники отображают `ID`, `Название`, `Дополнительные сведения`, `Действие` — столбца «Строка Excel» и поля `excelRow` в их JSON больше нет. Сравнение с Excel идёт через fixture и порядок ID.

### Испытания

```bash
node examples/cash/build-demo.cjs
node tests/cash_crud.test.cjs
python3 tests/compare_excel.py tests/fixtures/cash_input.xlsx dist/html_dbms_cash_demo.html
python3 tests/browser_cash_ui.py
python3 tests/browser_cash_acceptance.py
```

`browser_cash_acceptance.py` запускает **полную HTML-оболочку и реальный RPC через sandboxed iframe**, проверяет отмену/подтверждение операции, создание справочника, добавление/изменение записи, запрет дубликатов, добавление транзакции, проверку истории, экспорт и повторное открытие скачанной копии. Из-за политики тестовой среды браузерный тест использует отдельный **заведомо небезопасный криптографический shim** для адресации/шифрования тестовой копии. Это **не проверка криптографической стойкости**, тестовые ciphertext не попадают в распространяемый HTML. Реальный AES-GCM, SHA-256 и сравнение данных проверяются независимо `cash_crud.test.cjs`, builder и `compare_excel.py`. Проверка локального `file://` с реальным Web Crypto остаётся отдельной задачей #31.

## Синтетический fixture

Дополнительное обезличивание: 32 новые категории, 1641 новых комментариев, новые текстовые описания типов и Excel-примечания; суммы, даты, критерии и кэшированные числовые итоги сохранены. Исходные строки комментариев не помещаются в новую версию fixture. Старые commits Git не очищаются автоматически. Это не гарантия полной анонимности остальных полей.

## Публичная учебная «Касса» — GitHub Pages (#38)

Целевой адрес: [netkeep80.github.io/html_dbms/](https://netkeep80.github.io/html_dbms/). До первого утверждённого развёртывания ссылка может возвращать 404. Публичная касса строится **с нуля**, исключительно из `examples/cash/synthetic-pages.cjs`: 720 искусственных операций, 12 типов транзакций, вымышленные справочники, суммы, даты и примечания. Генератор не читает XLSX, старый demo HTML или приватные записи. Старая Excel-derived fixture используется только регрессиями; её сохранённые числовые значения не предназначены для Pages. История Git не переписывается.

```bash
python3 build.py
node examples/cash/build-pages.cjs dist/pages/index.html
node tests/pages-data.test.cjs
python3 tests/browser_pages.py  # Playwright Chromium, HTTPS, реальный Web Crypto
```

Проверка расшифровывает все 23 физические записи, сверяет genesis/patch каждого документа и полный набор физических ID с синтетическим источником, отклоняет скрытые и orphan records, изменения истории, повреждения. Отдельная приёмка HTTPS проверяет автоматическое открытие «Кассы», журнал, аналитический view, валидацию, запись и повторное открытие скачанной копии без crypto shim. Перезагрузка сайта возвращает опубликованный snapshot, изменения посетителя на сервер не записываются. Сеть разрешена только для первоначальной загрузки самого документа; нет внешних API и библиотек.

Workflow `.github/workflows/pages.yml` запускается после успешного Subject tests and build для актуального push в main или вручную на main при наличии успешной проверки того же коммита. Он формирует только `site/index.html`, проверяет его, и публикует через GitHub Pages environment. Первый deploy и последующие изменения синтетического набора требуют явного согласования владельцем SHA-256 содержимого fixture в `examples/cash/pages-approval.json` (формат `{"fixtureSha256":"<64 hex>"}`). Отсутствие файла или несовпадение хеша запрещает deploy. После утверждения неизменного fixture обновления приложения публикуются автоматически при успешном CI. После deploy отдельная проверка сверяет SHA-256 опубликованного файла и запускает браузерный HTTPS smoke. Настройка Pages: Source → GitHub Actions. 

Публичный файл содержит доступный всем ciphertext и публичный HEAD; это не механизм конфиденциального доступа. В публичное окружение никогда не передаются Excel-файлы, старые дампы, HEAD реальных баз или весь репозиторий.

## Денежная модель #45 (новые сборки)
`amountMinor` — безопасное целое число копеек, от −9007199254740991 до 9007199254740991; ввод десятичной строки с точкой или запятой, максимум два знака, без экспоненты. Отрицательные суммы сохраняют направление и знак; -0 канонизируется в 0. Агрегаты BigInt, форматирование без Number, округление запрещено. Геометрия SVG допускает приближение, подписи точны. Отчёты: период включительно и ДД = Да; журнал: период и текстовый поиск без фильтра ДД, обороты фонда. Сохранённые ранее demo HTML — исторические snapshots; новый build не переписывает их в Git. Числовые источники принимаются только как безопасные целые рубли, дробные требуют исходной десятичной лексемы. Старые XLSX регрессии не публикуются на Pages.

Внешние проверки: `node tests/cash-money.test.cjs`; `python3 tests/cash-oracle.py` (утверждённые 720 операций, seeded fractional/permutations, независимый integer oracle); `python3 tests/compare_excel.py` (оригинальные Decimal-лексемы, сверка всех шести отчётов, диагностика кэша); `python3 tests/browser_cash_exact.py` (новый синтетический snapshot, нативная криптография, 33/34 категории, большие обороты, UI, сохранение и история). Новые приватные или Excel-derived артефакты не коммитятся.

Сборщик без выходного аргумента создаёт новый файл во временном каталоге ОС и печатает его путь; явный выход обязан отсутствовать, запись с `wx`. Исторический `dist/html_dbms_cash_demo.html` не перезаписывается. CI и автономные регрессии строят отдельные временные snapshots. Python oracle сначала проверяет каноническую строку целого BigInt (без дроби, экспоненты, лишних знаков, ведущих нулей), затем сравнивает целые копейки.
