# HTML_DBMS/3 — нормативные требования (без legacy)
## Physical container
```json
{"format":"HTML_DBMS/3","publicHeads":{"Касса":["ID","H"]},"records":{}}
```
- `publicHeads` необязателен; отсутствует или частичный для скрытых баз. Имена произвольны, значения строго `[ID,H]`. `records` — плоская map ID → ciphertext; несколько независимых БД в одном HTML. Открытие по внешнему head всегда разрешено. Публичный каталог — каталог публикации, не доказательство актуальности/наличия.
- Никакого чтения v2.x, legacy конвертера, fallback.
## JSON chains
- Одинаковый generic JSON engine для всех цепочек, без политик `main`/`transaction`. Genesis закрепляет `name`, `parent` (= root head перед созданием или null для самостоятельного root) и начальный JSON `state`; genesis криптографически детерминирован.
- **Обязательный компактный формат Patch без `seq`**: `[timestampISOUTC,prevID,prevH,patchArray]`, где `patchArray` непустой массив RFC 6902. Время сохраняется, но не является доверенным удостоверением времени. Порядковый номер вычисляется по длине проверенной ancestry и не сериализуется. Genesis: `[null,{"name":"...","parent":null,"state":{}}]` (или `parent=[ID,H]` при создании из выбранного корня). Нет дублирующего `"patch"` и `{patch:...}`.
- JSON Patch RFC6902, JSON Pointer RFC6901. Все цепочки просматриваются и воспроизводятся с криптографической проверкой.
- Address genesis: `first16(SHA256(Hgenesis))`; successor: `first16(SHA256(IDprev || Hprev))`; AES-256-GCM при фиксированном IV из ID, H=SHA256(UTF8(JSON.stringify(record))) и Key=H. Сохраняются поведение `SUCCESSOR_OCCUPIED`, explicit physical overwrite, диагностика broken ancestry; без скрытого автоматического удаления.
- Сейчас **нет** CBOR / MessagePack / Brotli / DEFLATE / byte prefix: оптимизация сериализации отложена. Остаётся JSON UTF-8 как byte representation.
## Namespaces and references
- При открытии root `R` его `R.$refs = { name: [ID,H] }` задаёт плоское пространство имён. Для произвольного документа локальная ссылка `{"$ref":"/a/b"}` читается в том же документе, внешняя `{"$ref":"funds/F001/name"}` — относительно неизменного выбранного root snapshot. Внешняя оставшаяся часть `/F001/name` — JSON Pointer; `funds/` целый документ. `entry` может содержать JSON непосредственно или `{"$ref":"app/main"}`. Вложенные `$refs` не меняют namespace, пока документ не открыт как root.
- Циклы, отсутствующие refs, некорректные pointers, лимиты рекурсии должны диагностироваться.
- Исторические root snapshots удерживают исторические head дочерних документов; при записи дочернего документа appends: child → root patch `/$refs/name` → optional `publicHeads[dbName]`, на staging store, без автоматического публикуемого указателя для скрытой БД.
## UI
- **Узкая верхняя системная панель**: выбор опубликованной БД / открыть по ID+H, создать БД / документ, сохранить HTML, копировать head, верификация/диагностика, режим публикации и debug.
- **Вся область ниже** — содержимое JSON выбранной БД/документа, рендер выбранного `entry` или универсальный JSON viewer/editor. Не захардкоживать схему кассы/склада. Любой код в JSON показывается как текст; исполнение хранимых JS — отдельный доверенный runtime и опциональный UI с явно предоставленными правами, не автозапуск.
- Экспорт HTML из чистого шаблона с заменой только `db-store`, без утечки расшифрованного DOM.
## Проверки
- Tests: create root/multiple DBs, missing and partial publicHeads, direct open of hidden DB, create/register child with genesis.parent=root head, generic Patch/load/history, namespace resolution, cycle/missing invalid pointer, occupied slot, corruption, export safety, thin UI toolbar, no legacy.

## Дополнение: строгая граница UI (уточнение требований от 2026-11-23)
**Системная оболочка:** узкая верхняя строка: название `HTML DBMS`, версия, кнопка **Новая**, список опубликованных БД, два редактируемых поля **ID**, **H**, кнопка **Открыть**, кнопка **Сохранить**, кнопка **Отладка**. Выбор пункта в выпадающем списке **только подставляет** `[ID,H]` в поля и **не вызывает load/open**. Кнопка «Открыть» всегда читает head непосредственно из этих полей. Рядом допускается меню дополнительных **системных** операций: загрузить HTML, копировать head, проверить цепочки, опубликовать или скрыть head.

**Вся прикладная функциональность под верхней строкой** задаётся исключительно значением `entry` открытого корневого JSON; в системной панели не должно быть кнопок документов, таблиц, JSON Patch, столбцов и т. п. `entry` может быть inline или `$ref` в дочерний документ. Если entry отсутствует — нейтральная заглушка вместо обязательного редактора. Для новой БД редактор можно записывать в сам `entry` как стартовое приложение. Исполняемый JS должен быть изолирован; произвольный внешний JS только по явной команде, запись через ограниченный API только с подтверждением. При экспорте отрисованное содержимое приложения не должно попадать в файл.


## Зафиксированный бинарно-текстовый wire-format

Genesis: `[null,{"name":"...","parent":null,"state":{}}]`.

Patch: `[timestampISOUTC,prevID,prevH,patchArray]`, ровно четыре поля; **seq отсутствует** и вычисляется по подтверждённой ancestry. Timestamp обязателен, но не заверяется внешними часами. `patchArray` должен содержать не менее одной операции RFC 6902.
