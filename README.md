# HTML DBMS / 3

Самостоятельная экспериментальная темпоральная NoSQL-СУБД в одном HTML-файле, с криптографически связанными версиями JSON-документов. Один файл может содержать несколько логических БД.

**[Автономный HTML: dist/html_dbms.html](dist/html_dbms.html)** — откройте локально в браузере с Web Crypto API. Сетевой сервис и установка не нужны.

## Использование версии 3.0.2

Чистый автономный HTML **намеренно не содержит предустановленных БД**. До первого создания выпадающий список отключён и сообщает «БД отсутствуют». После создания БД она немедленно доступна в текущей вкладке, однако состояние останется только в памяти, пока пользователь не нажмёт **«Сохранить»**. Браузер **скачивает новый HTML-файл и не переписывает** ранее открытый исходный файл. Для повторного открытия следует использовать скачанную копию.

При загрузке файла с публичными БД первая из них выбирается автоматически **только для подстановки ID и H**. Кнопка «Открыть» всегда работает с введёнными полями. Выбор другой БД в списке не заменяет уже открытое приложение до явного нажатия «Открыть».

Новая БД содержит встроенное стартовое приложение непосредственно в JSON `entry`. Оно **автоматически исполняется** в ограниченном iframe (только для неизменённого доверенного шаблона) и показывает панель «+ Документ / JSON Patch / Обновить» с признаком **«Приложение запущено»**. Исходный JS-код в рабочем представлении корневого JSON скрыт; он доступен в системной «Отладка». Для произвольного JS `entry` нужна явная кнопка запуска.

## Формат HTML_DBMS/3

```json
{
  "format": "HTML_DBMS/3",
  "publicHeads": {"Касса": ["physical-id", "hash"]},
  "records": {"physical-id": "base64url-ciphertext"}
}
```

`publicHeads` необязателен: может отсутствовать полностью либо перечислять только часть БД. Скрытые БД открываются по известному `(ID,H)`. `records` — физическое плоское хранилище всех криптографических цепочек; каталог является каталогом публикации, а не наличия или авторизованности.

### Компактные сообщения без `seq`

```json
["2026-11-23T18:00:00.000Z", "ID_prev", "H_prev", [{"op":"replace","path":"/x","value":1}]]
```

Формат Patch: `[timestamp, prevID, prevH, operations]`. Порядковый номер вычисляется при чтении по длине ancestry и **не сохраняется**. Время фиксируется, но не удостоверяется доверенным источником. Пустой Patch не принимается.

Genesis: `[null,{"name":"...","parent":null,"state":{}}]`. Для дочернего документа `parent` равен head выбранной корневой БД непосредственно перед созданием. Универсальные JSON-цепочки — без `main` и `transaction` политик.

JSON Patch — RFC 6902, локальные JSON Pointer — RFC 6901, `{"$ref":"/path"}` адресует текущий документ, `{"$ref":"funds/F001/name"}` разрешается через `$refs` **выбранной версии** корневого JSON. `entry` может содержать данные непосредственно или ссылку; стартовый редактор хранится в `entry` как JavaScript. Произвольные JS-программы запускаются только по команде в изолированном iframe, операции записи требуют подтверждения.

### Криптография и ограничения

Сериализация: JSON UTF-8; дополнительное сжатие, CBOR и MessagePack в v3 **не включены**. SHA-256, AES-256-GCM, детерминированные генезис- и successor-адреса сохранены; занятый successor не перезаписывается без отдельного подтверждения. Старые форматы 2.x не открываются и не мигрируются в этом коде.

**Экспериментальная безопасность:** ключ AES в этой схеме производится из SHA-256 исходного содержимого и не гарантирует конфиденциальности предсказуемых сообщений. Для чувствительных данных необходим независимый криптографический аудит.

### UI

В одной узкой верхней строке расположены **HTML DBMS / 3.0**, **Новая**, выбор опубликованной БД, поля **ID** и **H**, **Открыть**, **Сохранить**, **Инфо**, **Валидация**, **Отладка**.

- Выбор в списке **только заполняет ID/H**. Кнопка **Открыть** использует поля, а не элемент списка. Изменение полей само по себе не меняет открытую версию.
- **Инфо**: сведения о контейнере и текущем head, загрузка другого HTML, копирование ID/H, публикация/скрытие.
- **Валидация**: проверка контейнера, корневых и дочерних историй, доверенного исторического H, сравнение с внешним HTML как данными, диагностика повреждений и отдельно подтверждаемое восстановление. Скрытые цепочки без известного head невозможно проверить автоматически.
- **Отладка**: просмотр сырых расшифрованных событий в режиме read-only; данные не попадают в экспорт.
- **Всё прикладное содержимое ниже** определяется `entry` выбранного корневого JSON. Новая БД содержит стартовое приложение (JSON viewer/editor, создание документов, JSON Patch), которое запускается в sandbox iframe. Произвольные JS entry исполняются только вручную; запись требует отдельного подтверждения.

## Стабилизация 3.0.2 (аудит)

- Проверка `verifyDatabase` проходит по **всему историческому** `$refs`, включая удалённые позднее документы; rollback через `remove → re-add` отклоняется с `REFERENCE_ROLLBACK`. Проверяются криптографические ancestry всех ранее опубликованных дочерних голов.
- Список опубликованных БД — одноразовый выбор источника ID/H. После выбора он возвращается в пустое состояние; **Открыть** использует только поля ID/H. При ошибке открытия прежний iframe удаляется, а запись при изменённых полях ID/H запрещена до явного нового открытия.
- Кнопка «+ Документ» использует обычную форму с полем имени и начального JSON прямо в `entry`, не вызывает запрещённый в sandbox `prompt()`.
- Конфликт `SUCCESSOR_OCCUPIED` предоставляет **отдельное явное подтверждение** физической перезаписи; при отмене рабочая копия остаётся неизменной. При обновлении дочернего документа подтверждения для дочернего и корневого successor независимы. Прежняя история после такой операции может стать недоступной — это преднамеренное свойство разрешённой физической перезаписи, а не признак успешной проверки старых snapshots.
- Сравнение другого HTML даёт независимые списки `missingIds`, `addedIds`, `changedIds`; панель «Инфо» показывает размер JSON-хранилища в байтах.
- Тесты: `node tests/core.test.cjs`, `node tests/app.test.cjs`, `node tests/docs-language.test.cjs`, `python3 tests/browser_smoke.py` (Chromium + тестовый **небезопасный** crypto shim только для UI). Никакой security guarantee browser smoke не даёт; криптография проверяется Node Web Crypto.

Стабилизация не меняет протокол сообщений `HTML_DBMS/3`. Legacy v2 по-прежнему не поддерживается.
